FUNCIONES Y METODOS: API

La carpeta api es la capa presentación de nuestro proyecto en el caso del backend, esta expone los datos a la web

- deps.py: get_db y get_current_medico (exige Authorization: Bearer <token>; 401 si falta, es invalido o expiro)
- routers/
	- auth.py (implementado, prefijo /api/v1/auth):
		- POST /registro: crea la cuenta de un medico (usuario en minusculas, contrasena 8-128 caracteres). 409 si el usuario existe
		- POST /login: {nombre_de_usuario, password} -> token de sesion. 401 con el mismo mensaje si falla el usuario o la clave
		- GET /me: perfil del medico de la sesion (sin password ni efirma)
	- pacientes.py (implementado, /api/v1/pacientes, todo con sesion de medico):
		- POST: crea (CURP unica, formato validado; 409 si existe). GET: lista paginada con ?buscar=&limit=&offset=
		- GET /{id}, PATCH /{id} (parcial; null borra telefono, tipo de sangre y notas), DELETE /{id} (409 si tiene citas o consultas)
		- el directorio es compartido entre medicos: el esquema no liga pacientes con medicos
	- citas.py (implementado, /api/v1/citas): cada cita es del medico de la sesion; las de otros medicos devuelven 404
		- POST agenda (hora sin segundos; 404 paciente inexistente, 409 horario ocupado, 422 fecha pasada)
		- GET lista con ?desde=&hasta=&paciente_id=&limit=&offset=, GET /{id}, PATCH /{id} (reprogramar o cambiar paciente), DELETE /{id}
	- consultas.py (implementado, /api/v1/consultas): una consulta guarda el diagnostico que confirma el medico
		- POST registra (la edad se calcula con la fecha de nacimiento; se genera la llave de acceso). GET lista las PROPIAS
		  con filtros paciente_id, enfermedad_id, desde, hasta. GET /{id} y PATCH /{id} (corregir diagnostico, peso, altura, notas): solo el autor
		- POST /acceso {llave}: abre en solo lectura la consulta de otro medico con la llave que le da el paciente. 404 si no coincide
		- no hay DELETE: son parte del expediente
	- catalogo.py (implementado, /api/v1/catalogo): GET /enfermedades (con su id para enfermedad_id), GET /enfermedades/{id} (con sus sintomas)
	  y GET /sintomas (?solo_modelo=true: solo los que entiende el modelo). Sus nombres son los que acepta /ml/predecir
	- consultas.py (nota): operaciones relacionadas con capturar consultas
	- historial.py: historial de consultas realizadas
	- dashboard.py: retorno de datos específicos consultados
	- ml.py (implementado, prefijo /api/v1/ml):
		- POST /predecir: {sintomas: [...], top_n} -> enfermedades probables con probabilidad. 422 si un
		  sintoma no esta en el vocabulario del modelo, 503 si el modelo no esta cargado
		- GET /estado: si hay modelo cargado, su version y sus metricas de test
		- /predecir exige sesion de medico; /estado es publico
